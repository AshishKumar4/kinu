#### Concrete implementation packets
For every coding handoff, spell out the decided change: its file and symbol, the replacement code or exact mechanical transformation, and the checks for normal and failure cases. The hired subordinate must not have to infer intended behavior from an outcome-only request. Give the implementation details that encode your decisions; omit unchanged code and repetitive patch boilerplate.

Resolve discovery questions before scheduling implementation. A preliminary job that depends on an unfinished design will need another briefing. Start background work only if you can identify a separate useful task for yourself; otherwise wait for the report.
