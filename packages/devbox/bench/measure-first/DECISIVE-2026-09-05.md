## Recommendation (2026-09-06, run `kinu-devbox-bench-20260906084719`)

**Keep snapshot-chain as the default.** The driver refuses to rank this
run, and the measured challenger separately fails its request-count claim
and whole-tree publication workload. An index cap increase would conceal
neither cost. No default change is proposed: the existing
`DEFAULT_DEVBOX_STRATEGY = 'snapshot-chain'` in `src/storage.ts:256`
and its `src/devbox.ts:713-714` selector are unchanged. Merkle-pack stays
in the strategy/benchmark arm list as a **measured negative**, so this
comparison can be run again; it is not deleted or promoted.

Correctness work landed anyway: lifecycle ordering and genuine driver
retries, canonical hardlink capture, and v2 restored-inode boundary handback
with parent-pack reuse. The 6.14 exemption was deleted only after its
red-first reproduction passed. The report's local section below records

1,014 passed, one skipped, none failed; the driver/admission pair passed
264 tests. `bun run check` and the commit tier passed on the correctness
commit. The live run on that clean commit establishes the remaining
negative; it does not turn the local v2 result into a deployed v1 result.

What remains unproven is explicit: G3 cut recovery for either arm, the two
bare-`Error` sqlite-fill causes, and successful merkle-pack git/sqlite
checkpoint costs. The instrument's incomplete blank cell remains a G6
refusal. These gaps are not timeout increases, known-red exemptions or
claims of admission. The measured negative is complete without pretending

### Local repairs (2026-09-06, run `local-merklepack-capture-1`)

Cell 6.14 was red without its exemption: the first in-place seal after wake
failed with `A generation cannot retire a pack it adds`. The v2 attach
cannot enumerate layouts locally: the root references lazy records. It now
seeds the published head without walking it, then binds each faulted file
layout to the inode the new container planted, before that file can be
written. This preserves sparse holes and adds no wake reads. After eviction,
exact re-read, and a 64 KiB overwrite in the 64 MiB file, the 08:39:35Z
measurement was 132,740 B staged, 81,920 B chunked, 160,253 B put in three
objects, zero whole files, and three wake operations. The 6.14 exemption
is removed. A separate lost-boundary-map regression failed before the fix:

## Publication-cut instrument measured locally on 2026-09-06

The driver now uses a stored-object acknowledgement rendezvous.
`packages/devbox/bench/publication-bucket.ts` selects it from the Worker boot
setting `BENCH_PUBLICATION_CUT`. The driver sets that value with
`--fault-cuts` before the proxy starts. Without the flag, G3 refuses.
No arm default, arm list, admission budget or admission gate changed.

After a PUT or multipart completion stores a nonempty object, the armed
wrapper holds its acknowledgement. `BenchOpCounter` persists the operation
token, store prefix, object key and a `PublishWork` row. The driver checks
that the checkpoint is pending. The fixture then confirms a running
container, kills it and waits for its stopped state before recording CUT.
A checkpoint that settles before this rendezvous records NOT-CUT.
The existing recovery judges still decide publication safety after CUT.
A held request alone cannot pass G3.

The boot choice leaves ordinary measurements unchanged. This command uses
local Miniflare R2 and reads back each written body:

```sh

```

| armed instrument | 5 | 3 |

The sequence contains two PUTs and one multipart upload. The armed wrapper
