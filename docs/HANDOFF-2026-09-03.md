## 3. Does the self-evolution loop implement GEPA?

The algorithm matches the paper. The evidence does not. `core/src/evolution/gepa/engine.ts` is the paper's loop:
seed scored on the full eval set, a Pareto-front pool with per-instance
dominance weighting for parent selection, reflective mutation from
per-instance score plus natural-language feedback traces (`mutate.ts`), the
Appendix-F Merge operator on complementary pairs (`merge.ts`), and budget
accounting by metric call.

What the automatic lane optimises is the text of one prompt section. Its
metric is not a rollout. `renderSectionScorePrompt`
(`control.ts`) asks one judge model "given this recorded response, would
this wording have produced one at least this good?" GEPA's minibatch
feedback and the "held-out trials" that promote a winner
(`runPromptSectionTrials`) use that same counterfactual guess. They run it
on different recorded turns. A chat turn cannot be replayed against the
same user. Nothing here measures behaviour. It measures a judge's opinion
of wording. Promotion is by win rate over three trials of that opinion.

The lane that rolled out (`runScaffold`) optimised `scaffold/agent.js`.
The chat turn never executes that file. It is off the tick as of `ba6d55f8`.

Has it ever run automatically in production? The trigger chain is:
`engine.reviewTurn` grades each turn (thumbs, else one `tiny`-tier
classifier call on your next message, else the execution verdict; a
failed last tool call grades as `corrected`). Three ungraded negatives
open a refinement request. The refiner is a temporary agent that reads
`context_ref` files. Until `ba6d55f8` those refs named files that do not
exist in a standard workspace, so every refinement refused before it
started. The prompt-section GEPA lane needs an eval split with both
accepted and negative labelled turns. Check `gepa_runs` in the hardy-stone
DO to see whether it ever completed one there. Nobody had seen one.

GEPA runs as a search procedure over a weak proxy metric. Its promotion
rule reads the same proxy. Whether that is worth its judge calls is
unmeasured. Count promoted sections in `prompt_section_versions` across
your workspaces before spending more on it.

## 5. The defect classes, and what a fix must cover

I found these in one day. Each has a fix in this branch, plus the class
behind it.

1. Seams tested only with fakes. The refiner test asserted the string
   `AGENTS.md` against a scripted refiner. The port that refuses absent paths
   was tested with its own fake. `createTool` admitted anything. The sandbox
   that would reject it never ran in the same test. The Devbox alarm sweep
   ran only inside a hook that never fires while the container sleeps.
   Fixed cases now cross the real seam (refiner against real VFS, crafted source
   against real workerd). The class needs a rule: a test of a producer/consumer pair
   builds both sides from production code, or says why it cannot.
2. Prompt-driven behaviour with no measurement. The nudges are gone. The rule
   going forward: a prompt sentence that steers behaviour carries the measurement
   that justified it, or it does not land.
3. Platform limits assumed, not measured. Facets share the root's
   isolate, and a swarm node ran an npm install in it. `gate:platform` already
   refuses an unnamed number. The guard names `worker.isolate.memory`.
4. Ten-subsystem commits. `7ba56550` landed the refiner bug and nine
   other subsystems in one commit. Each part was green in isolation.
   Integration was unowned. This branch is eleven commits, one concern each.
   Keep it that way.
5. Machinery that spends money on nothing. The scaffold GEPA lane spent
   569k input tokens in one workspace on an artifact the turn never ran.
   It is off. I have not yet audited five more lanes with the same question
   ("who consumes this lane's output?"): sleep-time updates, curriculum proposals,
   alternate takes, shadow trials, advisor reviews. Do that audit before anything
   else in §6. Each is a lane with model calls and a mocked test island.
6. Gates that check text and shapes, not behaviour. Examples: prompt-byte
   ceilings, manifest sets, constructor-signature string assertions. They
   stay. Weakening a gate is forbidden. They still do not prove a turn works.
   The workerd sandbox test is the pattern to copy: the real thing, exercised.

- The stash/pop cycle used to classify failures against `origin/main`
  drops staged deletions from the index. The anti-slop gate reads
  `git ls-files`, so a deleted file needs `git rm --cached` before the
  gate goes green again.
- `~/.kinu/cli.log` on this device holds the `kinu create` failure trace

  checkout whose valibot resolved from `../Proteus/node_modules`. A bundle
  built in a borrowed-modules worktree is the trap the worktree section
  of AGENTS.md describes. `bun run build:scanner` from a clean tree fixed
  it. `gate:scanner-bundle` caught it.
- A `git stash` baseline proves a failure is not in the DIFF. It does not
  roll back `node_modules`, so a failure caused by a dependency bump
  survives the stash and reads as pre-existing. Probe one such failure
  for its own message before writing it off. Two classes here were
  misfiled that way for an hour.
